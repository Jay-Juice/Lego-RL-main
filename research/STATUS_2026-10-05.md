## Speed investigation

The old 51.6-minute run used the old batch16-trained step80 model, not the original
base. Matching 469 tasks shows the original base's old and new trajectories have
almost identical workload (about 79 calls and 3.6M cumulative input tokens).
Old step80 used about 60 calls and 1.8M input tokens. Historical base ran at 2/8
concurrent trials per GPU; the recheck ran at 32. Cache reuse degraded at the
larger concurrent long-history workload. Per-request eviction evidence was not
recorded, so this does not establish every cache-miss cause or an optimal concurrency.
See [paired evidence](handoffs/SAO_RESEARCH_2026-09-29/historical_base_matched_analysis_20261005.json).

## Operational boundaries

Machine paths and archived launchers are historical operational records, not
portable defaults or authorization to execute them. Preserve all new checkpoints,
HF models and results; no automatic retention watcher. Do not run global Ray or
Docker cleanup, restart shared Docker, modify shared environments, or use the
system disk for large artifacts. PI implementation should use a separate,
explicitly reviewed experiment and retain Actor/Critic information boundaries.
